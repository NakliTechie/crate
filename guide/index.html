Crate · user guide

Your personal cloud folder, in a bucket you own.

Crate is a single web page that turns a storage bucket you control into an encrypted cloud folder. Your files are encrypted in this browser before they leave it. Nobody on the way — not Cloudflare, not us — can read them without your passphrase.

This guide walks you through setting up a folder for the first time, using it day-to-day, opening it again on another device, and the design choices that make all of this work.

Live at crate.naklios.dev. Source on GitHub. AGPL-3.0-or-later.

1What you're getting

In one paragraph: a tab in your browser that looks like a file manager, backed by a storage bucket you own (Cloudflare R2 by default — set up for you in one click). Drop files in; they encrypt on your machine; the bucket stores ciphertext. Open the URL on your phone with the same passphrase; the same folder appears. Optionally run a small daemon on your laptop and the same folder lives at ~/crate/ as regular plaintext files.

What makes it different from Dropbox / iCloud / Google Drive:

  • The bucket is yours. You pay Cloudflare directly (free tier covers most users — 10 GB storage, 1 M writes, 10 M reads per month). You can leave Crate at any time; your files stay in your bucket.
  • The encryption is in this browser tab. The bucket owner sees only ciphertext and access patterns. We can prove that — the entire encryption layer is one file: lib/crypto.js.
  • No account with us. There's nothing on a NakliTechie server. The whole app is static HTML; you could host it yourself off any static server tomorrow if our deployment vanished.
  • Two credentials you hold, none we do. Your passphrase, and a 24-word recovery phrase for the day you lose it. No recovery email, no support backdoor. That's the trade-off.

2Before you start

You'll need three things in front of you, all free:

  • A Cloudflare account. Takes 60 seconds at dash.cloudflare.com/sign-up. No card needed for Crate's usage. Your helper Worker and your bucket live there.
  • A GitHub account. github.com/signup. Cloudflare copies Crate's tiny helper into it when you deploy; the first time, Cloudflare asks to connect the two accounts (a one-off consent screen).
  • Somewhere to write five words down. The wizard shows you a five-word passphrase; you write it down and tick a box. (Prefer your own? There's a link for that — the bar goes green at five unrelated words, and you may go lower after seeing the cost.)

Time: the deploy itself takes about a minute; allow a few more the first time for account sign-up and the GitHub connection.

heads up Crate cannot recover your passphrase. If you forget it AND lose your credentials file (you'll get one at the end of setup), the files in your bucket are unreadable random bytes forever. Plan for redundancy — see section 6.

The page opens as a file manager — sidebar, search, and this card in the middle. How it works (on the card and in the top bar) opens a short explainer: the privacy promise plus how Crate works in three steps, with a Full setup guide button that expands the detailed Cloudflare walk-through.

There are two ways in. Get started is the one to use unless you already run your own bucket and API token (then Use a bucket you already have, under the card). (If you've onboarded already and you're back, see section 5.)

The one-click path

Click Get started. The wizard has three stages: Carrier → Passphrase → Done. "Carrier" is a tiny program (a Cloudflare Worker) that Cloudflare deploys into your account, holding a bucket it creates for you. It only ever sees encrypted bytes, and deleting it ends its access.

  1. Copy the secret. Crate shows a connection secret it generated for you. This is not your passphrase — that comes later. Click Copy secret.
  2. Deploy. Click Deploy to Cloudflare ↗. On Cloudflare's page: pick your GitHub account (first time only, Cloudflare asks to connect it), paste the secret into the CARRIER_SECRET field, leave everything else as suggested, click Deploy.
  3. Wait about a minute — then reload. Cloudflare's build page does not update by itself. Reload it; when it says deployed, click Visit.
  4. Continue to Crate. The Worker's own page has one button. It brings you back to the wizard with the Worker's address already filled in. (If you closed the tab, paste the address — it's https://crate-carrier-….workers.dev, shown under Workers & Pages in your Cloudflare dashboard.)
  5. Verify, then Next. Crate checks the Worker is up and the secret matches. Click Next →.
  6. Passphrase and Done — same as below, from "Stage 4" onwards.
what you never do No API token, no CORS policy, no account ID. The only thing you paste is the secret, once. What you keep afterwards is the .crate-creds file (downloaded at Done) and your passphrase — nothing else.

why we ask The CORS JSON tells Cloudflare which web origin is allowed to talk to your bucket from a browser. It does not give Crate or anyone else read access to your files — it only controls headers Cloudflare sends back. The actual files are still encrypted before they ever leave your tab.

Stage 4 — Passphrase (both paths)

The wizard shows you five random words, numbered, and the passphrase they make when joined with hyphens — sphere-cancel-scan-blanket-interest. Write that line down exactly — on paper or in your password manager — tick I've saved the hyphenated passphrase, and click Next. (Crate's own unlock screen also accepts the words with spaces; the desktop daemon wants the hyphens.) That's your passphrase: about 55 bits of strength, roughly 60,000 years for one GPU to exhaust, and words are far easier to copy correctly than symbols. Different words deals a new set. The words come from the public 2048-word BIP-39 list, shipped inside the page; the strength is in the random choice, not the list.

Next comes your recovery phrase: 24 words, shown once. If you ever lose the passphrase, these open the folder and let you set a new one. Write them on paper, in order, then type three of them back to continue — or Skip for now and set one up later from Backup. Don't screenshot the phrase; don't email it to yourself.

Prefer to choose your own? Click I'd rather choose my own passphrase. You'll type it twice; the strength bar (zxcvbn) turns green at the recommended 55 bits — five unrelated words, or twelve random mixed characters. Below that, the page tells you how long one GPU would need to crack it and lets you accept the trade-off with a tick; only the trivial (under 20 bits — a single word, a birthday) is refused outright.

Save what you'll need to reopen this folder

Download your credentials file and keep it with your passphrase. On another device you unlock with this file + your passphrase. The file holds your connection details, encrypted — it does not replace your passphrase, and it is useless without it.

do this now Click ↓ Download credentials file before opening your folder. You'll get a small file named <name>.crate-creds. Save it the same way you'd save a backup password — a password manager, an encrypted USB. Anyone with this file and your passphrase can read your folder; either alone is useless. From now on the two things you keep are this file and your passphrase — every other device unlocks with exactly those.

The shell

The frame you landed in stays: the sidebar on the left switches views, the search box at the top filters whatever list you're looking at, and the ··· menu at the top right holds Refresh from storage and Lock. The footer of the sidebar keeps a running total — size, file count, and the word encrypted.

  • All files — the folder tree. Click a folder to open it; the breadcrumb under the title takes you back up.
  • Recent — the 50 most recently added or changed files from anywhere in the tree, newest first, each with the folder it lives in.
  • Photos — every image in the tree (by type or extension), with a count next to the label. A list, not thumbnails: showing thumbnails would mean decrypting every image on open.
  • Trash — deleted files, for 30 days. Restore, delete forever, or empty the lot.
  • Devices — this browser, plus Pair an agent for the desktop daemon. See section 7.
  • Backup — Set up a recovery phrase (if you skipped it at setup), Change passphrase, Re-key folder (a fresh encryption key, for when you suspect the old one leaked), Set up a passkey (Touch ID / Face ID / a security key opens the folder on this device), Download credentials file (re-emit the encrypted .crate-creds at any time), and Export everything (a zip, or a stream to a folder on disk for large collections).

The toolbar

  • ↑ Upload — open a file picker, or drag files directly onto the page. They encrypt + upload one at a time.
  • New folder — empty folders are recorded as explicit events in the manifest so they survive across devices.
  • ··· → Refresh from storage — pulls the latest manifest from the bucket. (Sync is automatic every ~15 s; this is for impatient checks.)
  • ··· → Lock — zero the master key, clear in-tab session state, return to the start screen. Use before leaving the laptop unattended.

Per-file actions

Hover any file row (on a phone they are always shown) and the modified date and size give way to the actions:

  • Preview — open text, images, PDFs (your browser's own viewer), audio and video inline without downloading. Files larger than 50 MB show a "too large to preview, use Download" message.
  • Download — decrypt + save to your Downloads folder. Large files stream straight to a destination you pick on disk.
  • Share link — a URL that lets anyone who has it download this one file for an hour, a day or a week; nothing else in your folder is reachable. Rotate your carrier secret or R2 token to cut every link off early.
  • Rename — pure manifest event; the underlying ciphertext is unchanged on the bucket.
  • History — see every change to that file: when it was created, every update + size delta, any rename, the delete if present. Read from the manifest already in memory; no network call.
  • Delete — moves the file to Trash. It stays there for 30 days and can be restored (to its old place, or as name (restored) if the old name is taken); after that its data is removed from your storage. Delete forever and Empty trash remove data now.

Search

The search box in the top bar filters the list you're looking at — the current folder in All files, or the whole of Recent / Photos — by name, case-insensitive. It clears when you navigate. In All files it also searches inside text files once you've let Crate index them (one click under the results; the index stays on this device, encrypted, and refreshes incrementally).

Drag-and-drop

Drag files from your desktop / Finder / Files app onto the folder area. The whole UI lights up with a "Drop to upload" overlay; release to upload. Each file is encrypted in this tab, then PUT to your bucket.

Mobile

The same URL works on a phone. The folder UI is responsive; actions are always visible (no hover-to-reveal on touch devices). Upload from your phone's photo picker works for images and most file types.

The fallback — no file

If you lost the credentials file (or you're on a brand-new device and haven't transferred it yet), click No file? Enter the details manually. Choose how you set up:

  • One click (carrier): the Worker URL (under Workers & Pages in your Cloudflare dashboard) + the carrier secret + your passphrase. Lost the secret too? Set a new CARRIER_SECRET on the Worker (Settings → Variables and Secrets) and use that — the old one stops working, which is also how you revoke a lost credentials file.
  • My own bucket: bucket name, Cloudflare Account ID, Access Key, Secret Access Key, passphrase.

Either way, re-download a fresh .crate-creds file from Backup → Download credentials file once you're back in.

Refresh keeps you logged in

If you accidentally hit ⌘R / F5 mid-session, you don't go back to square one. The encrypted credentials blob lives in your tab's sessionStorage (passphrase-encrypted; useless without your passphrase). On reload, the wizard sees the blob and goes straight to "Welcome back to name. Enter your passphrase to reopen it." One field instead of five (or two).

The blob dies when you close the tab or click 🔒 Lock. So a hard quit + relaunch goes back to the full unlock screen.

6Backup & recovery

Your bucket is your only copy of the files by default. If you lose access to it (account closed, accidentally deleted, ransomware on your Cloudflare account), the files are gone unless you've made a copy somewhere else. The encryption that keeps Cloudflare from reading your files also means Cloudflare can't restore them for you.

Three independent redundancy options:

  1. Run the desktop daemon (recommended). crate-agent keeps a plaintext mirror at ~/crate/ on macOS or Linux. Point Time Machine, restic, rsync, or whatever you already use at that folder. The plaintext lives on hardware you control.
  2. Mirror the bucket. rclone sync r2:bucket-A r2:bucket-B, or use Cloudflare's R2 → R2 replication. Ciphertext-preserving; restore = swap creds in the wizard.
  3. Export from the browser. Backup → Export everything gives you a zip of everything. One-shot — use the daemon for recurring backups.

Three disaster scenarios

You lost the passphrase, but have the recovery phrase

Open Crate → Already set up? Open your folder → Lost your passphrase? Use your recovery phrase. Enter your connection details (the creds file can't help — it's sealed under the lost passphrase), paste the 24 words, and pick a new passphrase. Nothing in the folder is touched.

You lost the passphrase and the recovery phrase

Files are gone, with or without the creds file — there is no reset, no support email, no backdoor. Plan ahead: the recovery phrase on paper, the passphrase in a password manager.

You lost the creds file, but have the passphrase

Fine. Use the 5-input manual unlock to get back in, then use Backup → Download credentials file to download a fresh file.

You lost the bucket

Restore from whichever redundancy you set up: daemon's local folder, rclone mirror, or exported zip. Create a new bucket; same passphrase; you're back.

Full runbook: docs/backup.md.

7The desktop daemon

crate-agent is a small Go binary that keeps a folder on your laptop in sync with your Crate. It runs as a background service; you edit files in ~/crate/ with any tool (vim, VS Code, drag-drop in Finder), the daemon encrypts + uploads them. Browser-side changes download + decrypt to the same folder.

The daemon never holds your R2 access keys. With a one-click folder it talks to your carrier Worker using the same carrier secret the browser uses (ciphertext-only access); with a hub-based setup it pairs via a one-time token. Either way it never sees plaintext in transit — it decrypts on your machine, with your passphrase.

Pair + start

One-click folder (crate-agent v1.3 or later):

  1. In Crate, open Devices and click Pair an agent. The modal shows the exact command and a button that copies your carrier secret.
  2. In a terminal: crate-agent pair --carrier https://crate-carrier-….workers.dev. Paste the carrier secret, then type your folder passphrase. It verifies against the Worker and runs doctor.
  3. crate-agent start to run in the foreground, or crate-agent install-service to install as a launchd / systemd-user unit that starts at login.

Hub-based folder: Devices → Pair an agent shows a CRATE-PAIR-… token + QR code with a 15-minute countdown; run crate-agent pair, paste the token, type your passphrase, then doctor and start as above.

Once running, ~/crate/ is bidirectional with the browser within ~15 seconds. Full daemon docs in the crate-agent repo.

8Security model

The short version of the full crypto design:

  • Master key = PBKDF2-SHA256 of your passphrase + a 16-byte random salt stored in .crate/crate.json. 600,000 iterations (OWASP 2023 recommendation). Lives only in this browser tab's memory.
  • Per-file data keys = fresh 32 random bytes per file, wrapped by AES-256-GCM under the master key. Sealed with the file's UUID as additional-authenticated-data so a row-swap attack on the bucket fails authentication.
  • Payload sealing = AES-256-GCM with the per-file data key + a fresh 12-byte IV per write.
  • Signed manifest = JSONL log of every event (create, update, delete, move, mkdir), each event HMAC-SHA256-signed with the master key; each event carries the previous event's signature → tamper-evident chain. The entire manifest is then encrypted at rest.
  • Credentials file = your connection details (for a one-click folder: the Worker URL + carrier secret; for your own bucket: name, account ID, access key, secret key) in a JSON envelope encrypted with AES-256-GCM under a key derived by PBKDF2-SHA256(passphrase, salt). Independent salt from the bucket's salt; useless without the passphrase.
  • Concurrent-write safety = ETag-conditional PUT (If-Match) with replay-on-412. Two tabs PUTting at the same time → second one gets 412 → re-GET, splice pending events on top, retry up to 3 times.

What we explicitly don't protect against

  • Compromise of your browser tab while it's unlocked. If a Chrome extension can read your tab's memory, it can read your master key + every file you touch. Same as 1Password and other client-side crypto apps. Use a clean profile if this matters.
  • Side-channel access patterns. Cloudflare sees the number of objects you have, their sizes, and when you touch them. They cannot see the content.
  • Future cryptanalytic breaks of AES-256-GCM or PBKDF2-SHA256. If either falls, every app using them falls together. We'd migrate via a v2 wire format.

Crate is AGPL-3.0-or-later. The entire encryption layer is lib/crypto.js. Every network call lives in lib/bucket.js. The credentials-file format is lib/credsfile.js. There is no telemetry, no analytics, no backend.
